# 次方針の決定：moment を dense に、population を TT に置くハイブリッド衝突

作成日：2026-10-06
前提資料：`README.md`、`docs/direction_review_2026-10-05.md`（改訂2）、研究側の技術回答、N128 B 保存 step2 の A/B 計測結果（2026-10-05）
付属：`scripts/toy_moment_hybrid_timing.py`、`docs/toy_moment_hybrid_results.json`（擾乱 81%）、`docs/toy_moment_hybrid_results_eps0.1.json`（擾乱 27%）

---

## 0. 決定

**停止する枝**：TCI で非線形 BGK 写像を点標本化する現行構築の改良。具体的には、検査 metric の事前計算（A）、凍結基底への投影（B）とその基底拡張、pivot 戦略・warm 修復の改良、添字順序や 6 コア分離の優先検討。

**採用する枝**：次の二つを一組で進める。

1. **構築の仕組みを変える。** moment（ρ, j の 4 場）を TT から厳密に縮約して dense に持ち、平衡分布の oracle を O(1) にする。平衡分布 f_eq = Σ_{i=1}^{10} v_i(q) m_i(x) の TT を、既存の fixed cross 機構に oracle だけ差し替えて構築する。f* = (1−ω) f + ω f_eq_TT は TT 和と丸めで作る。モデルは標準 BGK のまま、ρ の除算は dense で厳密に行う。
2. **検査の構造を変える。** f_eq の厳密参照が安価になるので、f_eq 部分は全面・全域で直接検証し、丸め誤差は SVD の切捨て量で大域保証する。現契約を維持する変種 I と、面の端到端比較を「f_eq 面検証＋丸め台帳＋H 点端到端（毎更新）＋面端到端（k 更新ごと）」へ置き換える変種 II を、別軌道で両方測る。変種 II は保証変更であり、失うものを 3 節に明記する。

**順序**：単一保存状態（B 保存 step2）→ 一更新と次更新 → 32 更新。停止条件は 4 節で事前に固定する。

---

## 1. 根拠

### 1.1 A/B 計測の読み

- **A**（応力 einsum の方向積事前計算）：数値等価、更新時間比の中央値 0.970、第 1 組 1.248。採用しない。検査の metric 側に大きな余地はない。
- **B**（完全 population を F1 固定基底へ縮約）：費用門は代理比 0.917 で通過したが、完全 target の基底外成分が E_out/‖F‖ = 5.73e-8 で、1e-8 予算の 5.7 倍。棄却。基底拡張は追わない。せん断流では擾乱の位相が y 依存で進むので基底は毎更新変わる。合成場でも、位相を 10 ステップ分進めた近傍状態の f_eq rank は 26/10 から 43/13 へ増えた（2 節）。基底を固定して追いかける設計は、動く対象を追うことになる。

### 1.2 構造的な下限

B 方式 fixed31 の 1 更新あたり費用は、検査 0.47 秒、差引残 0.325 秒、dense 0.69 秒。検査を変えない限り、どの構築法でも TCI/dense ≥ 0.68。構築だけを改良する枝は、成功しても比 1 を少し切るのが上限になる。構築と検査を同時に変える必要がある。

### 1.3 なぜ moment を dense にするか

- BGK の非線形性は moment 空間（ρ, j の 4 場 → 10 係数場）にしかない。population は 27 場。現行 TCI の oracle 1 要求あたり約 2 μs は、source TT を点で評価して 27 方向を取り出し moment と f_eq を計算する経路が主である。moment を一度 dense 化すれば（q 縮約は rank 保存、dense 化は行列積 2 回）、oracle は 10 項の積和になる。
- f_eq = Σ_{i=1}^{10} v_i(q) m_i(x) は q 側 rank が厳密に 10 以下で、v_i は (qx, qz, qy) の積形をとる。現行 paired 配置と相性がよく、変換は不要。
- 厳密な f_eq が全点で安価に得られるので、f_eq TT の検証を面でも全域でも直接行える。TCI 内部収束と全域精度の乖離という問題が、f_eq 部分では消える。
- f* の組立は TT 和と丸めで、丸めの Frobenius 誤差は切捨て特異値から既知。
- README の「六場からの毎更新再構成・sum/round」との違い：係数場を個別に TT 化して和を取り丸めるのではなく、(a) 係数場は dense のまま、(b) f_eq の TT は O(1) oracle の cross で直接作り、(c) 和と丸めは f と f_eq_TT の 2 項に対して 1 回だけ行う。

## 2. 合成場による計時

### 2.1 条件

`scripts/toy_moment_hybrid_timing.py`。BLAS/OMP/MKL 各 1 スレッド（研究側と同条件）。格子 128×32×128、D3Q27、τ=2.036、paired 配置。合成場は改訂 2 と同じ 4 モード擾乱。状態 TT は f を 1e-8 で TT-SVD したもの。f* の絶対予算は 1e-9‖f*‖ とし、f_eq 側に 0.5e-9‖f*‖/ω、丸めに 0.5e-9‖f*‖ を配分した。dense 参照は同じ NumPy で 27 方向ループの BGK 衝突と 27 回の roll による streaming。

合成場の dense 更新は衝突 0.50 秒＋streaming 0.21 秒 ≒ 0.71 秒で、研究側の dense 0.69 秒/更新と一致する。計時の尺度は研究側と揃っている。

### 2.2 結果

| 項目（秒、中央値 3 回） | 擾乱 27%、状態 rank 25/12 | 擾乱 81%、状態 rank 33/12 |
|---|---:|---:|
| dense 衝突 | 0.502 | 0.535 |
| dense streaming | 0.207 | 0.251 |
| moment 4 場の dense 化（厳密、最大相対差 2e-8 は状態 TT の誤差） | 0.006 | 0.007 |
| 10 係数場 | 0.015 | 0.016 |
| f_eq の fixed cross（pivot は現 f_eq の TT-SVD 由来） | 0.007（rank 20/10、raw 85,440） | 0.011（rank 26/10、raw 110,784） |
| f_eq の fixed cross（pivot を 10 ステップ前の近傍状態から継承） | 0.020（rank 37/12、raw 185,856） | 0.023（rank 43/13、raw 232,416） |
| TT 和＋丸め | 0.028 | 0.048 |
| **構築合計（現 f_eq 由来 pivot）** | **0.056** | **0.082** |
| f_eq の面検証（y=2、全 27 方向、厳密 f_eq 対 TT） | 0.015 | 0.023 |
| f* の全域誤差 / 面誤差 y2・y16・y31 | 2.2e-9 / 1.6e-9・2.0e-9・2.2e-9 | 3.5e-9 / 1.3e-9・3.1e-9・5.2e-9 |

- 構築合計は dense 衝突の 0.11〜0.15 倍。研究側の fixed 差引残 0.325 秒と比べても 1/4〜1/6。
- f* は全域・全面で 1e-8 を満たした。擾乱 81% では f_eq cross の誤差 2.0e-9‖f*‖ が配分予算 1.0e-9 を 2 倍超えたが、f* 合計 3.5e-9 は 1e-8 内。pivot を近傍状態から継承した rank 45/15 の cross では 3.9e-11 で予算内。実装では rank 適応を 1 回許す。
- 継承 pivot で rank が現 f_eq の rank を超えると pivot 行列の条件数が 1e14〜1e16 になった。誤差は予算内だったが、実装では最小二乗または剪定で安定化する必要がある。
- randomized TT-SVD は cross の約 30 倍遅く、fallback にしかならない。

### 2.3 限界

元研究の場・実装ではない。TT 上の streaming・reflection、境界 packet、ghost 面、history、現行の資源判定は含まない。pivot 継承は位相を進めた合成場で模したもので、実軌道の次更新ではない。dense 参照は NumPy で、最適化実装ではない。したがって 2.2 の比は、研究側の fixed 差引残 0.325 秒のうち構築に属する部分の見込みであり、更新全体の比ではない。

## 3. 検査の構造変更（保証変更として明示）

現契約の F 検査は、候補 f* を面上で BGK(source) と比較する。ハイブリッドでは候補の誤差が二項に分解される。

‖f*_TT − BGK(f)‖_面 ≤ ω‖f_eq_TT − f_eq‖_面 ＋ ‖丸め‖_面

- 第 1 項は厳密 f_eq が安価なので面上で直接測れる（合成場で 1 面 15〜23 ms）。
- 第 2 項は丸めの Frobenius 誤差 δ が SVD から既知で、面の絶対誤差 ≤ δ。面 norm は ‖F‖/√32 程度なので面相対誤差 ≤ 5.7·δ/‖F‖。δ = 1e-9‖F‖ なら 5.7e-9 < 1e-8。

**変種 I（契約維持）**：F/P/H、ledger、kernel を全て残す。参照 BGK のうち f_eq 部分は dense moment から安価になるが、source の面評価（(1−ω)f 項）と候補の面評価は残る。期待する検査費用の低下は限定的で、数値は Step 1 で測る。

**変種 II（保証変更）**：面の端到端比較を、f_eq 面検証（毎更新・全 F 面）＋丸め δ 台帳（毎更新）＋H 256 点の端到端比較（毎更新、fresh）＋面の端到端比較（k 更新ごと、k は 4〜8 で先に固定）に置き換える。
- 得るもの：標本ではない大域 Frobenius 保証。面評価 2 本（source と候補）が k 更新に 1 回になる。
- 失うもの：和・丸め・面組立・streaming 経路の実装不良を、毎更新の面で検出する能力。H 点と k 更新ごとの面で部分的に補う。独立第二経路による故障検出の頻度低下として記録する。
- 変えないもの：数値閾値、P/H の対象と頻度、ledger 1e-9、kernel 1e-14、finite 判定、保存量拒否、rollback。

## 4. 試験計画と停止条件

### Step 1：単一保存状態（B 保存 step2、現契約）

a. source（bulk、dense2、interface packet、ghost 面）から moment 4 場を dense 化する。既存の面参照で使っている moment と 1e-14 以内で一致することを確認する。
b. 10 係数場を作り、現行 TCI 機構の oracle を差し替えて fixed cross を走らせる（pivot は現 F1 由来）。raw 要求、固有点、時間、rank、受理経路を記録する。
c. f_eq TT を全 F 面と S_f/H 点で厳密 f_eq と比較する。配分予算 0.5e-9‖F‖/ω を超えたら rank 適応を 1 回だけ許す。
d. f* = (1−ω)f + ω f_eq_TT を和と丸め（δ = 0.5e-9‖F‖）で作り、現行 F/P/H・ledger・kernel をそのまま適用する。
e. a＋b＋d の合計時間を現行 fixed 差引残 0.325 秒と比べる。

停止条件：c で rank 適応後も予算超過。d で現契約不合格。e で合計が 0.325 秒以上。合成場の見込みは 0.06〜0.1 秒。

### Step 2：一更新と次更新

streaming・reflection・packet を通して次入力を作り、次更新で moment 化と pivot 継承（前 f_eq TT の pivot）が成立するかを確認する。pivot 行列の条件数を記録し、継承 rank が現 rank を超えたときは最小二乗または剪定を使う。失敗候補の費用を含めて計時する。

停止条件：次更新で受理不合格、または次更新の費用が Step 1 を 1.5 倍以上上回る。

### Step 3：32 更新（B 方式）

変種 I で現契約のまま TCI/dense を測る。dense 対照は同条件で再計測する。合格後、変種 II を別軌道で測り、両方を並べて報告する。累積 velocity、壁 shear、warm 発生率、rank 推移、全点 chunk 診断は現行通り。

予測は Step 1・2 の実測から事前に書く。合成場の見込みでは、変種 I で 0.6〜0.8、変種 II で 0.3〜0.5。いずれも仮説。

### Step 4：判断

変種 I で比が 1 を切らなければ、N128 帯は TT の計算優位を示せる領域ではないと結論し、記憶・IO 優位の領域（面内 N ≥ 512、dense 帯が GB 規模）へ対象を移すか、研究を区切る。変種 I で 1 を切り変種 II でさらに下がれば、C 方式（壁面補正あり）へ同じ構成を展開する。

## 5. 却下・保留

- 凍結基底の拡張、観測者台帳の書換え、H2、quantics、R 省略、許容値緩和：却下または保留のまま。
- 添字順序・6 コア分離：ハイブリッドで構築費用が小さくなると意義が薄い。残る論点は streaming 費用との兼ね合いだけで、Step 2 の計時を見てから判断する。
- randomized TT-SVD：cross の fallback としてのみ保持。
- 1 モード・N256 の軌道試験：Step 3 の後。N256 は取得経路と workspace の資源入場確認が前提。

## 6. 3 問への最終回答

1. **差を減らす見込みが最大の方向**：構築を moment-dense ハイブリッドに変え、同時に検査の参照を安価にすること。構築だけでは比 0.68 の下限を越えられない。有望条件は変わらず、低 rank・面内 N の大きい層流〜遷移初期の低 Mach 流。
2. **局所改善か、計算法・表現変更か、モデル近似か**：計算法変更（構築の oracle と組立）と検査構造の変更。モデル近似はしない。表現変更は後回し。
3. **最小の反証**：Step 1 の単一保存状態で、予算・契約合格・費用門の三つが同時に通るかで決まる。通らなければ、この枝も N128 帯での計算優位の主張には使えない。
