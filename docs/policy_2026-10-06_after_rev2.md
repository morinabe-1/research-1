## 0. 要約（修正後）

現在の N128 保存入力では、moment-dense によって前計算と fixed 候補構築の一部は短縮したが、fixed 候補は面 y2 の velocity guard で棄却され、warm を含む完全 attempt は 10.876528 秒だった。受理後の完成 F 全域相対 L2 は 3.79947541e-9 である。現実装・現契約では native dense（0.077479 秒）が大幅に速いため、研究資源の配分として N128 の速度優位追求を停止する。これは現入力・現実装・現契約での未達であり、一般的な不可能性の主張ではない。

次に検証するのは、実際に受理した Eq 専用履歴の次更新への継承と、構造付き randomized TT-SVD による代替構築である。合成場では有望な例が得られたが、条件数上限の超過や誤差不合格もあり、実入力の精度・費用・資源契約への適合は未確認である。

容量と長時間挙動の研究では、TT core payload、全保持状態、workspace、peak RSS を分けて報告する。完成 F の全域保証を主張する前に、全域 Eq 構築残差、source 近似、round、浮動差を含む誤差台帳を定義する。変種 II は、population だけでなく velocity・stress・finite を含む毎更新の採否契約を明示し、局所一更新誤差と独立 dense 軌道に対する累積誤差を分けて検証する。

## 2. 局所一更新の誤差台帳

同じ正確な source S に対する完成候補 F̂ の局所一更新誤差は、source 近似 S̃、Eq 構築、丸め、浮動差に分けて

‖F̂ − BGK(S)‖₂ ≤ |1−ω|‖S̃ − S‖₂ ＋ |ω|‖Êq − Eq(S)‖₂ ＋ δ_round ＋ δ_float

で管理する。各項の扱い：

- **source 項**：packet 埋込と source round の絶対上界を同じ参照に対して合成する（rev2 の上界 5.05394146e-8 は絶対値で、相対誤差や Eq 残差と同じ量ではない）。Eq を S̃ から作る場合は Eq(S̃) − Eq(S) の非線形摂動を別に評価する。密度下限なしに線形 source 誤差へ吸収しない。
- **Eq 構築残差**：cross で作った Êq は、全 F 面と H256 点で一致しても未検査内点の誤差に決定論的上界が付かない。選択肢は三つ。(i) 全域厳密残差を z-slab で評価する（費用は dense 衝突相当。毎更新なら速度は失うが、速度は目的ではない。k 更新ごとでも可）。(ii) randomized TT-SVD で射影残差の事後推定を含む台帳を持つ（確率的。失敗確率と probe 列数を明記）。(iii) cross に事後の randomized 残差推定を付ける（確率的）。cross＋面＋H だけの段階では全域 1e-8 を主張しない。
- **丸め**：各 round 内は tail の二乗和、別 round 間は上界加算。直交化済み TT の round に限る。
- **浮動差**：1e-8 級の小残差を差し引きで計算する際の桁落ちを含めて予約する（rev2 の floating 予約 7.436e-8 に相当）。
- **面相対誤差**：丸め寄与は δ / max(‖F_面,ref‖₂, 1e-30)。対象面の実際の参照 norm か証明した下限を使い、Eq 面誤差と source 誤差を加える。平均的な面 norm は使わない。
- **局所と軌道**：各時刻の局所誤差 ε_t が小さくても、独立 dense 軌道に対する累積誤差は E(t+1) ≤ L_t E(t) ＋ ε_t で伝播する。「32 更新で全域 1e-8」は、各更新の局所 F 誤差か、32 時刻の独立 dense 軌道との差か、必ず限定して書く。

事前予算 B = 1e-8·N_F0 の配分を定めることと、各項の実現誤差が配分内であることを示すことは別である。表には分母（‖F‖ か ‖Eq‖ か）、絶対か相対か、配分予算か最終 guard かを記載する。

## 3. 変種 II の採否契約（項目別）

変種 II は、完成 F の物理量判定の毎更新面実測を間引く契約変更である。各項目について次を定める。

| 検査項目 | 変種 I（現行） | 変種 II の提案 | 失うもの |
|---|---|---|---|
| F population | 毎更新、全 F 面と S_f 256 点で実測 | S_f 256 点は毎更新実測。面は 2 節の合成上界（source＋Eq 残差＋round＋浮動）で毎更新判定し、端到端の面実測は k 更新ごと。合成上界が閾値を超えたら端到端へ戻す | 面の毎更新実測。合成上界が Eq 残差の確率的推定を含むなら決定論性 |
| F velocity | 毎更新、面と S_f で実測 | S_f・H で毎更新実測。面は k 更新ごと。合成上界から velocity を保証するには Δu = (Δj − uΔρ)/(ρ＋Δρ) の密度下限と参照速度 norm が要り、現時点では保証を主張しない | 面上の毎更新 velocity 判定 |
| F stress | 同上 | 同上。小参照 norm 時の相対誤差 0 扱いと絶対誤差記録の特例は維持 | 面上の毎更新 stress 判定 |
| finite | 面・点の派生量で毎更新 | 候補 TT の全コアと明示面、点評価値の finite は毎更新。面評価を行わない更新では面上の派生量 finite を失うので、全コア finite と点 finite で代替し、非有限は即拒否 | 面上の派生量 finite の毎更新判定 |
| 面端到端 | 毎更新 | k=8、対象は現行 2 面。失敗時は直前 k 更新分の受理 F を rollback し再検証する（TT 状態は小さいので k 個保持できる） | 失敗検出の遅延 ≤ k 更新 |
| H | 凍結後 1 回 fresh | 現行維持。構築・rank 選択・乱数 sketch に使わない | なし |
| P 共有 | 同一候補・同一参照条件で F 結果を共有 | 現行条件を維持。面端到端を間引く更新では P の fresh 評価を維持する | なし |
| ledger・kernel | 毎更新 | 現行維持 | なし |

変種 II は独立した契約として定義し、変種 I と同じ入力で並走させて差を表にする。

## 5. 主張範囲の限定

### 5.1 native dense との比較

同じ材料化 dense 配列を使った native 全更新 0.077479 秒、NumPy 全更新 0.641757 秒、native と NumPy の全 27 方向差 maxabs 1.11e-16 は有用な比較である。ただし、dense 配列が既にある場合の native 更新、TT 入力の材料化 1.857450 秒を加えた経路、TT＋明示面を出力し F/P/H を行う研究経路、独立に発展する登録 dense 軌道対照は別の比較対象で、目的別に両方を報告する。

「どの構築法・検査契約でも届かない」「NumPy で最善でも 0.3 秒」「構造的」は未証明として撤回する。既存区間の時間はアルゴリズム全体の下限ではなく、flop 数が同桁でも実時間の大小は決まらない。毎更新 4 回の面評価という前提は変種 II には当てはまらない。旧 decision の「構築費用がゼロでも 0.68」も、当時の検査時間を固定した条件付き見積りに限定する。

### 5.2 容量の比較範囲

B 方式の TT 保持層は y2..31 の 30 層で、rank 25/18 の TT core は 8 × (384×25 ＋ 25×384×18 ＋ 18×90) = 1,472,160 bytes。これに対し 32 層全帯の dense population 一配列は 113,246,208 bytes、30 層分なら 106,168,320 bytes。約 1/77 は「TT core のみ」と「32 層全帯 dense 一配列」の比であり、同じ範囲の全状態の比ではない。B 方式の dense 2 層、packet・ghost の明示面、Eq 履歴 TT と pivot、moment 場は別途必要で、32 時刻の全保存容量と一時刻の状態容量も別である。報告では TT core、全保持状態、workspace、peak RSS（rev2 の OS lifetime peak は 851.266 MiB、source/assembly の LAPACK workspace 見積り 25.291 MiB とは別 scope）を分ける。

### 5.3 N 依存性と N512 の資源

rank と帯厚を固定すれば paired TT core は O(N) だが、dense 2 層、明示面、moment 場、係数場は O(N²)。全保持状態や peak RSS まで ∝N とは言えない。N512・帯厚 32・float64 では dense population 一配列は 1,728 MiB で RSS 上限 1280 MiB に置けないが、現 toy fallback もそのままでは入らない。10 係数場 640 MiB、転置コピー 640 MiB、4 moment 全帯 256 MiB で上限を超える。chunk 化、配列寿命の整理、workspace 入場、資源契約の再登録が必要で、dense を「不可」とする比較では TT 側にも同じ上限を適用する。rank の N 非依存性と費用定数は仮説であり、物理領域・波数・振幅・時間・許容値・演算 backend を揃えた試験条件を先に定義する。

## 6. 構築変更に必要な前提条件

### 6.1 source を明示平面のまま運ぶ案

f* = [(1−ω) bulk ＋ ω Eq] ＋ (1−ω)(packet ＋ ghost) の分離は、元の source の定義が一致する限り代数的には合理的だが、それだけでは契約不変ではない。確認する項目：

- Eq の moment が bulk だけでなく定義上必要な全 source 成分から計算されること
- packet・ghost を加法項として扱う範囲と、境界の上書き・置換規則が一致すること
- streaming、reflection、B offset、dense 2 層、受理 history で成分を欠落・二重加算しないこと
- F/P/H が bulk TT 単体ではなく、最終的に受理・輸送される候補全体を参照すること
- 省く round と残る round を反映して source 誤差台帳と資源会計を再定義すること

0.167→0.05 秒、1 面 0.065→0.01 秒、全体 0.45 秒は仮説であり、実測の結論に使わない。

### 6.2 Eq 履歴と新 fallback の管理

- Eq 履歴の保存対象（コア、pivot 集合、条件数）、pivot 抽出費、更新時点、失敗時の rollback
- 予約 S_f/S_w/H 点を構築・rank 選択・乱数 sketch に使わない扱い
- 非有限・資源超過と、許可された精度拒否・condition 拒否の区別
- 追加 rank と workspace の事前入場
- 最大試行回数、失敗費用、診断費用を含む会計
- 全域診断を構築へ還流させる場合は、その利用を別契約として明記する

toy は全係数場を使い、元研究の予約点・境界・受理契約を再現していない。toy の成功だけで新 fallback を同一契約に適合済みとは扱わない。面評価の行列積化は数式・対象点・最終候補を保った実装改善として試せるが、finite、例外、offset、H の独立性を含む既存 fixture での同等性確認が要る。

## 7. 停止条件（精度・容量・費用・N 依存を独立に判定）

1. **Eq 履歴 fixed が実入力で失敗**：その構成を既定経路にしない。cross 一般の不可能性とはしない。変更した rank・予算・条件数処理を記録する。
2. **32 更新で fixed 成功率 < 90%、または更新費用の最大/中央値 > 3**：費用・運用上の採用条件の不成立。fallback 込みで精度・容量が成立していれば、それらの結果は残す。
3. **N256 で Eq の第 1 bond rank が N128 の 1.5 倍以上**：事前に定めた「ほぼ一定 rank」仮説の棄却。許容値と入力場のスケーリングを固定し、一回の比から漸近計算量を結論しない。
4. **実測全域誤差が台帳上界を超過**：保証違反として停止。原因は台帳定義の欠落、実装不良、参照・分母の不一致、浮動誤差のいずれでもあり得るので、原因解明まで保証主張を止める。

精度、容量、費用、N 依存性は別の採用条件として報告し、負の結果も正確に残す。

## 8. 実行順序

1. **文書と表の修正**：fixed／warm、計時 scope、Eq 履歴全 5 例、条件数、予算分母。既存の保存結果だけで対応する（本改訂と `decision_2026-10-06.md` の正誤表で着手）。
2. **保証と採否契約の定義**：2 節の合成式と、3 節の変種 II 各 guard の扱いを先に固定する。randomized の射影残差は決定論的第二パスか確率的台帳かを選び、失敗確率を明記する。
3. **実入力の一更新と実次更新**：実際に受理した Eq 履歴（rev2 の warm Eq rank 23/13 を起点）を使い、次更新で条件数、完成候補の F/P/H、history、予約点、rollback、費用を確認する。
4. **fallback と資源の入場確認**：実入力と sheared 場について、k・power、最大 rank、全域誤差、失敗処理、peak workspace／RSS を確認する。
5. **その後に 32 更新と N256**：精度・容量・費用の条件を別々に判定し、初期準備、受理更新、棄却候補、診断の時間を分けて報告する。N256 は資源契約の改定と TT 側の chunk 化を前提にする。

残す方向：BGK の 10 方向基底分解、直交化した TT round の操作別誤差管理、native 対照の併記、Eq 専用履歴、N 依存性の仮説検証。修正したのは、これらの有望性を未確認の受理性能・全域保証・一般的不可能性へ拡張していた部分である。
