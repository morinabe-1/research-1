## 0. 要約

**結果の読み。** 受理 Eq2 の履歴を seed に、実 streamed state からの更新 3・4・5 がすべて fixed 経路で最終受理され、warm は 0 回だった。Eq fixed は 0.10〜0.12 秒、pivot 条件数は 6.0e8〜1.1e9 で上限 1e12 内、Eq rank (23,13)・F rank (25,18) は一定。全域 F 相対 L2 は 3.21e-9、3.17e-9、4.17e-9 で進行閾値 1e-8 内、累積 velocity は 5.4e-7→6.6e-7→8.7e-7、累積 wall shear は 9.6e-7→1.44e-6→1.46e-6 で gate（2e-5／1e-4）内だが増加している。これで rev2 の fixed 棄却（F1 由来 pivot）は Eq 専用履歴で解消されたことが、1 軌道・3 更新の範囲で実入力に確認された。

**費用の読み。** 数値更新は 2.07〜2.33 秒で、旧共有 B の 0.87 秒の約 2.4 倍、native dense 0.126 秒の約 17 倍。内訳の主項は F 選択・面検査 0.68〜0.85 秒、source 準備 0.42〜0.45 秒、P/H・stream・ledger 等の残り約 0.6 秒で、Eq fixed は 0.1 秒にすぎない。受理完了 20〜21.5 秒の 88% は全域 F/Eq 検査 13.4〜14.4 秒と累積検査 4.0〜4.8 秒で、これは研究進行 gate の費用である。速度は主張しない。

**決定。**
1. **32 更新（更新 6〜37）へ進む。契約・gate・pipeline・fallback は変えない。** 全域 F/Eq 検査と累積検査を毎更新の進行 gate として残し、測定された全域誤差を主張の根拠にする。S6 checkpoint と Eq5 履歴から開始し、失敗時はその場で STOP する。
2. **randomized fallback の入場試験は別の単一状態作業として並行**し、この 32 更新では使わない。既存の two-site warm を fallback のまま残し、発生回数と費用を記録する。
3. **費用最適化は 32 更新の後。** 0.87→2.1 秒の内訳は記録だけ取り、pipeline を触らない。
4. **主張の範囲。** 速度は主張しない。圧縮は TT 部分（1/72）と B 方式の全保持状態（約 1/12）を分けて報告する。保証は、2 節の合成式が今回の 3 更新で測定値を説明したことを観測として記し、台帳としての採用は 32 更新の全点で確認してから決める。
5. **N256 は 32 更新の後。** 物理スケーリングと資源契約を先に定義する。合成場での Eq rank 事前確認を付録 A に置く。

## 2. 決定事項と理由

### 2.1 32 更新へ進む（契約・pipeline 不変）

改訂2 の実行順序では「保証と採否契約の定義」と「fallback と資源の入場確認」を 32 更新の前に置いた。今回は次の理由で順序を入れ替える。

- 32 更新の契約は全域 F/Eq 検査と累積検査を毎更新の gate として含むので、台帳の定義に依存しない。台帳の各項（Eq 全域残差、round tail、source 上界）は既に毎更新記録されており、台帳は事後に測定値と照合できる（1.4 節の表を 32 点に拡張する）。
- fallback は既存の two-site warm のまま残す。今回 warm は 0 回で、小 fixture では condition 拒否と有限 accuracy 拒否からの 1 warm が動作確認済み。randomized fallback を軌道の途中で入れ替えると、warm 発生率と費用の解釈が混ざる。
- 速度は主張しないので、受理完了 20 秒／更新は制約にならない。32 更新で約 11 分。

**入口**：S6 checkpoint と Eq5 履歴。全 gate と precommit rollback を維持し、失敗時はその場で STOP。1 worker あたり 8〜16 更新で checkpoint を区切り、1800 秒制限内に収める。

**毎更新の記録**：Eq fixed の成否・時間・条件数、warm 回数と費用、Eq/F/source の rank、Eq requested scalars と unique points、段階別時間（1.2 節の列）、全域 F/Eq 相対 L2、round tail bound、source 上界、F/P/H/ledger の各 metric、累積 velocity・wall shear、peak working set、checkpoint hash 連鎖。

**追加する診断（構築へ戻さない）**：Eq cross の事後 randomized 残差推定（probe 16 列）を毎更新 1 回計算し、全域測定 Eq 残差と並べて記録する。変種 II で全域測定を代替できるかを判定するための材料で、採否・rank・pivot・rescue には使わない。費用は probe 1 回分（合成場で 0.1 秒未満）。

**停止条件（既存 gate）**：F/P/H/ledger の不合格、全域 F > 1e-8、累積 velocity > 2e-5、累積 wall shear > 1e-4、非有限、資源超過、rank cap 48。失敗時は STOP し救済しない。

**判定条件（停止ではなく採否の記録）**：
- 費用：fixed 成功率、warm 回数、更新費用の最大／中央値。fixed 成功率 < 90% または最大／中央値 > 3 なら費用決定性の主張を取り下げる。精度・容量の結果は残す。
- 台帳：全 32 点で 線形和 ≥ 測定 F 相対 L2 が成り立つか。1 点でも破れたら合成式の見直しまで変種 II へ進まない。randomized 推定が全域 Eq 残差を全点で覆うか（覆う割合と最大の下振れを記録）。
- 累積誤差：E(t) を a＋bt と a＋bt＋ct² で当て、32 更新時点の値と旧共有 B32（累積 velocity 最大 3.12e-6、shear 1.54e-5）を並べる。gate は変えない。
- rank：Eq・F・source の rank 推移。cap 48 到達前に増加傾向があれば N256 の rank 仮説に反映する。

**事後解析**：段階別費用の中央値と四分位、0.87→2.1 秒の内訳、圧縮会計（1.5 節）の更新ごとの値、台帳照合表。

### 2.2 randomized fallback の入場試験（並行、別作業）

実 S3（sheared）と Eq 履歴 rank 23 に対し、k = 23＋15 と 58、power 1 と 2 で構造付き randomized TT-SVD を走らせ、厳密全域 Eq 残差、射影残差の決定論的第二パス値と probe 推定、tail、関数時間、workspace を記録する。合成場の phase0・sheared 8 設定では厳密残差 4.65e-9〜7.1e-9 で Eq 相対許容 1.6288e-8 を満たしたが、実入力では未確認。失敗経路（残差超過時の k 拡張 1 回、再試行上限、停止）と予約点の非使用を fixture で確認する。採用判定は 32 更新の後で、two-site を置き換えるのは次の軌道からとする。

### 2.3 費用最適化は 32 更新の後

候補は改訂2 と同じ：source を明示平面のまま組立へ運ぶ案（sum-round を 2 回から 1 回へ）、面評価の行列積化、F 選択・面検査の内訳分解。いずれも契約不変の実装改善だが、32 更新の最中には入れない。32 更新後に単一保存状態で同等性 fixture を通してから採用する。

### 2.4 主張の範囲

- 速度：主張しない。数値更新 2.1〜2.3 秒と native dense 0.126 秒を並べ、受理完了 20 秒の 88% が研究 gate であることを明記する。TT 入力の材料化 1.86 秒を含む経路と含まない経路を目的別に報告する。
- 精度：各更新の局所全域 F 誤差（同じ TT 入力に対する BGK との比較、測定）と、累積誤差（共通 S2 から独立に進む native dense 軌道との比較）を分けて報告する。「32 更新で 1e-8」は前者の各更新値を指す。
- 圧縮：1.5 節の会計で、TT 部分 1/72、B 全保持状態 約 1/12 を併記する。
- 保証：1.4 節は観測であり、台帳の採用は 32 点の照合後。変種 II の各 guard（velocity・stress・finite を含む）の扱いは改訂2 の 3 節の表に従い、32 更新の結果を見て確定する。

### 2.5 N256 は 32 更新の後

前提として先に定義するもの：
- **物理スケーリング**：面内 N を 2 倍にすると dx が半分になる。音響スケーリングなら dt も半分で τ は 0.5＋(τ−0.5)/2 = 1.268、同じ物理時間に 2 倍の更新が要る。拡散スケーリングなら dt は 1/4。帯厚 32 層は物理厚さが半分になるので、32 層か 64 層かを決める。モード・振幅・準備時刻 t0 は物理量で固定する。
- **資源契約**：累積検査の native dense 軌道は N256 で 1 配列 453 MB、2 buffer で 906 MB となり、同一 worker の RSS 1280 MiB に TT 側と同居できない。別 process か chunk 化が要る。TT 側は moment field 64 MiB、係数場 160 MiB、suffix cap（8 MiB → rank 25 で約 14 MiB）、pair/workspace 上限の改定が要る。
- **仮説**：Eq・F の rank は N に依存しない（付録 A の合成場で事前確認）。payload は TT core で ∝N、dense 2 層と面で ∝N²。費用は O(N²) で定数が dense より小さい、という見込みは測ってから書く。

## 付録 A：合成場での N256 Eq rank の事前確認

結果は本節末に追記する。手順：`scripts/toy_moment_hybrid_timing.py` の格子寸法を環境変数で 256×32×256 と 256×64×256 にし、同じ物理プロファイル（半チャネル高さを 256 格子に）と同じモード番号で、Eq の TT-SVD 参照 rank と randomized 構築の rank・残差・時間を測る。仮説：Eq 第 1 bond rank は N128 の値（phase0 21、sheared 37）から 1.5 倍以内に収まる。

```
TOY_NX=256 TOY_NZ=256 TOY_NY=32 TOY_H=256 OMP_NUM_THREADS=1 python3 scripts/toy_randomized_fallback_check.py --eps 0.3 --out docs/toy_randomized_fallback_results_N256_Ny32.json
TOY_NX=256 TOY_NZ=256 TOY_NY=64 TOY_H=256 OMP_NUM_THREADS=1 python3 scripts/toy_randomized_fallback_check.py --eps 0.3 --out docs/toy_randomized_fallback_results_N256_Ny64.json
```
